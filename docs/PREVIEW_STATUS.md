> 記錄「預覽畫面」這條線：哪些已修完並驗證、哪些沒解決、下一步從哪裡切、
> 以及重建驗證環境的步驟。數據全部來自實機診斷報告。

## 1. 目前架構

- **播放**：系統播放器（AVPlayer）播整條時間軸合成，逐格由自訂合成器（CoreImage）產生
- **暫停／滑動／拖曳**：Metal 引擎上台，同時畫影片與浮水印（與匯出共用同一套疊加數學）
- **匯出**：與預覽同一顆合成器

## 2. 已修完並經實機診斷確認

| 問題 | 根因 | 驗收 |

## 3. 尚未解決（下一步唯一的靶）

**滑動預覽跟不上手指。** 決定性數據（實機 156）：

    滑動供格 渲染1237／新格96     ← 每秒畫 60 格，解碼器每秒只供得出約 5 張新畫面
    拖曳 seek 平均 63ms、最久 147ms

- 渲染沒問題、位置有送到、引擎在台上——瓶頸在「供格」
- 根因：滑動預覽用 AVPlayer.seek 逐格取圖，每發 100~200ms
- 正解方向：連續解碼供格（ClipReader 已為播放實作過），滑動順序解碼、
  倒退或跳遠才重啟解碼器
- 2026-08-30 曾實作一版（commit e55eb67），整合測試兩支未通過，已回退（e1affc5）。
  要再做必須有可反覆驗證的環境；難點在「滑動中重啟解碼器的時機」與
  「與 pump 保底供格的交接」

其他已知、影響較小：
- 供格節奏偶發 120~350ms 等待（合成器交格不夠即時）
- 快路（Metal 直拷）對 HDR 停用；SDR 快路未在實機命中

## 4. 診斷報告判讀

| 欄位 | 意義 |
| --- | --- |
| 交格亮度 | 合成器交出那格的亮度。0.063＝交黑格（合成端）；有值卻看到黑＝顯示端 |
| 滑動供格 渲染N/新格M | N 遠大於 M＝解碼器供不上（滑動不跟手的證據） |
| 上下台 | 引擎上/下台歷程；播放中出現「上」＝引擎又蓋上來 |
| 工作檔壞掉 | 轉檔被編碼器重置；>0 代表退回原檔，滑動必鈍 |
| 快路未命中原因 | Metal 直拷為何沒用上 |
| 供格節奏 | 系統播放器等合成器交格的時間 |

## 5. 重建驗證環境

1. Scaleway 租 Apple silicon M1（約 €0.11/hr，最短 24 小時）
2. 裝 Xcode、Flutter（~/dev/flutter）、Ruby/CocoaPods（~/dev/pruby、~/dev/gems）
3. git clone 專案到 ~/dev/markcut
4. 測試素材（關鍵）：必須有聲、HDR、帶旋轉、且會觸發工作檔轉檔——
   無聲或免轉檔的素材測出來的綠燈是假的
   - gen_vids.swift 產基本測試片
   - gen_audio.swift 把 440Hz 正弦波聲軌合進 HLG 影片 → ~/vids_extra/hdra.mp4
     （AVAssetWriter 產 AAC ＋ AVMutableComposition 合軌，passthrough 匯出）
5. run_itest2.sh <測試檔>：塞素材 → 跑整合測試 → 每 0.8 秒截圖到 ~/shots
6. 迴歸測試組：metal_scrub_test、audio_play_test、multitrack_play_test、
   instant_play_test、boundary_stress_test

## 6. 教訓

- 測試素材必須踩使用者的必經路徑（有聲＋HDR＋旋轉＋觸發轉檔），否則綠燈是假的
- 先量測再修：黑畫面猜了三輪都錯，加「交格亮度」探針後一輪定位
- 一個畫面只能有一個畫家：曾讓介面層與合成器各畫一次浮水印，播放與暫停顏色就不同
- 防護不能鎖死回饋路徑：「沒紋理就不渲染」讓取樣永遠不發生，畫面凍住
