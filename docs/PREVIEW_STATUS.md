# 預覽引擎現況與交接（2026-09-03 更新，Fresh-eyes 團隊重建後）

> 記錄「預覽畫面」這條線的最終架構、已定罪的根因、以及三條紀律。
> 歷史（2026-08-30 版）見 git 歷史；本版以團隊重建後的程式碼為準。

## 0. 三條紀律（來自外部架構體檢，已採納）

1. **一個畫面一個畫家**：畫面永遠只有系統 AVPlayer（合成播放器）。任何「上台/下台/讓位/回台」都是債。
2. **改樣式不准碰解碼器**：暫停中改樣式＝換一份新的 videoComposition 原地重畫（`CompPlayer.rerenderPaused`），不做假 seek。
3. **主執行緒不搬大位元組**：疊圖只烘元素外框（典型文字 ~240KB），不烘整張畫布。

## 1. 最終架構

- **播放**：AVPlayer(AVMutableComposition) + 自訂 CoreImage 合成器（預覽＝匯出同一顆、同一套 HLG 夾白/×3 數學）
- **暫停**：播放器停格（零換手）
- **滑動**：播放器 seek（代理轉正＋密關鍵幀後單軌 1~9ms）；放手一發精確 seek
- **樣式/幾何**：`lib/services/overlay_sync.dart` 狀態機——最新版直烘、單一在途、序號丟舊、80ms 節拍、靜默 500ms 一次全解析 → `setOverlays` → 原生換 vc 重畫
- **Metal 引擎**：合成在場時永不上台、永不預建（`_metalPrebuild` 第一行 `if (_compOn) return`）；只剩匯出/取樣用途
- **代理**：HDR 代理走 HDR 合成器烘正（方向烘死、HLG 標記寫檔、不動色調）；快取鍵 `#hdr6`

## 2. 團隊定罪的根因（我自己 100+ 版沒看到的）

| 症狀 | 真根 | 修法 |
| --- | --- | --- |
| 方向反了 | hdrPass 的旋轉合成器是死碼：純軌道輸出＋Resize 拉伸＝中繼資料完美、像素橫躺變形 | 統一走 `AVAssetReaderVideoCompositionOutput`、去 Resize、去 writer transform |
| 樣式閃爍（新→舊→新） | 合成器缺格時重播「含舊樣式的整格」 | `lastComposedBase`（不含疊加物）＋當下樣式重畫 |
| 樣式卡頓 | 每版兩發精準 seek＋預捲轟暫停中的 10-bit 解碼器 | 刪冗餘 seek、疊圖驅動後不預捲、最後改為換 vc 重畫 |
| 重建閃第 0 格 | 圖層一就緒就翻面，對位 seek 還沒落地 | `PlayerHosts.hold/release`：seek 落地才翻 |
| 每支代理一次重建 | 指紋含路徑＋存草稿計時器逐支觸發 | 整批一次 |
| 閃退風險 | 合成器統計無鎖被兩條佇列同時改 | `slowLock` |
| 陰影/粗細不對 | 畫家數學：描邊雙層透明度管壁、陰影透進字內、像素常數 | 單一群組透明度、字級尺度 |

## 3. 診斷報告判讀

| 欄位 | 意義 |
| --- | --- |
| 交格亮度 `…源亮X` | 輸出黑而源亮＝CI 染黑；源也黑＝解碼器交黑 |
| 催重畫 `N發/丟M/換件K次/vc換N延M` | vc換 應取代 發；換件應只在真正重建 |
| 拖曳 seek 平均/九成 | 單軌 <10ms、多軌 <40ms 為健康 |
| 浮水印管線 改變到上屏 | 九成 <100ms 為即時 |
| 互動事件流 | 上台/讓位/重建/斷流/卡格毫秒時間線；「引擎上台」在合成模式應為 0 |
| 軌道幾何 | 轉正代理應為 `WxH@0°`；出現 90° 即雙重旋轉 |

## 4. 工作法教訓

- 探針量中繼資料 ≠ 量像素；YDIF 靜止 ≠ 凍結（暫停畫面本來就不動）
- 同一症狀常是多個互餵機制；單修任一都「一樣」
- 卡死時派**乾淨上下文**的獨立審查者（不給既有理論、不信註解），一輪即定罪
- Swift 無編譯器：每批改動派「逐行審查員」當編譯器，通過才 build
- 測試素材必須踩使用者必經路徑（有聲＋HDR＋旋轉＋觸發轉檔）
