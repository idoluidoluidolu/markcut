# 預覽核心與互動優先排程

本次延續 `fc02011` 的冷匯入改善，處理首次進場、拖曳、播放與樣式更新互相搶資源的問題。前一輪紀錄見 [COLD_IMPORT_PREVIEW_2026_09_08.md](COLD_IMPORT_PREVIEW_2026_09_08.md)。

## 功能行為

- 多選影片先按選取順序接入中繼資料，再建立完整預覽。第一支素材的播放器建構不再阻塞後續素材接入。播放請求等待同一個準備流程，可取消，也會等待其間新增的批次；準備期間時間軸不假裝在播放。
- Android 預設不等待整批工作檔。背景準備优先服務播放頭下的上層素材，再處理可見及附近素材。排序只影響準備工作，不更改使用者的軌道與選取順序。
- 播放、拖曳、調整樣式優先於預覽轉檔。iOS 的 reader/writer 預覽工作可在影格間等待並繼續；Android 停止當前預覽轉檔，閒置後重排。Android 重排會重新轉該支，不宣稱保留已轉進度。正式匯出不受互動讓路控制。
- 取消準備不是編碼失敗，不降低畫質、不計入失敗重試，也不改走軟體轉檔。指標與樣式手勢有明確釋放和逾時回收，避免漏掉抬手事件後背景永遠停住。
- 支援的 iOS 原生 CI 預覽直接保留完成合成的像素緩衝，經共用的色彩管理顯示路徑呈現。Dart 不再為這條拖曳路徑抽 JPEG、解圖片或加 SDR 快取蓋層。其他平台和舊原生版本保留原來的後備路徑。
- 原生快取有位元組、影格數與時間窗口上限，內容、樣式、尺寸與請求世代不符就失效。暖幀使用現有播放和預熱產出的影格，不額外建立一組播放器或解碼器。
- 拖曳只追最新目標。精準收尾必須同時取得 seek 成功和 drawable 實際呈現收據；舊手勢回覆不能覆蓋新手勢或播放。全螢幕進度條也使用同一路徑。
- 樣式改變時保留已呈現畫面，等新內容影格完成再換上；播放、換檔、背景與記憶體清理分別處理。精準收尾多次失敗仍可保留畫面，但不永久阻塞背景準備，新手勢和新合成都能恢復。
- Android 抽幀器使用最多兩個來源的 LRU，依路徑、大小與修改時間辨識檔案，離頁和退背景釋放。Android 取樣沒有實際 PTS 時明確標為未知。
- 移除 Android 首次播放後的截圖與不同時間關鍵幀比較，避免額外解碼與誤判黑畫面。切換播放器只根據明確錯誤或初始化／首幀逾時；晚到的切換與 play 不得推翻使用者的暫停、定位或離頁。

## 色彩與呈現

新原生路徑使用既有 CI 合成結果，不重新實作浮水印、透明度、GIF 或馬賽克的效果數學。像素缓衝保留色彩附件；HDR 合成輸出以 HLG 色彩空間和十位元顯示目標傳遞，SDR 使用對應 SDR 目標。顯示收據來自 Metal drawable 的實際呈現回呼，不把送出命令當成已上屏。

參考 Apple：[HDR 顯示色彩空間](https://developer.apple.com/documentation/metal/using-color-spaces-to-display-hdr-content)、[drawable 呈現回呼](https://developer.apple.com/documentation/metal/mtldrawable/addpresentedhandler(_:))、[AVPlayer 最新目標 seek](https://developer.apple.com/library/archive/qa/qa1820/_index.html)。

## 驗證

本機完整 Flutter 回歸：**854 項通過、7 項需額外啟用的效能測試跳過**，包含既有畫面快照與實際 FFmpeg 圖像輸出。`dart analyze --format machine lib test integration_test` 無問題，`git diff --check` 通過。

Android 原生實際編譯及 JUnit **8/8 通過**。本機完整 APK 建置遇到中文路徑造成的 Flutter `impellerc` 崩潰，原生驗證用 CLI 跳過 Flutter shader 編譯，並关闭 Kotlin incremental cache 的跨磁碟限制；沒有把本機繞路設定寫入專案。裝置抽幀整合測試已加入，目前沒有連接 Android 裝置，未執行。

首輪 iOS 雲端基線 release 編譯成功，XCTest 抓出預熱時間點與真實剪接邊界相距 5ms 時的浮點誤判；已改用 CMTime 有理數比較，保留原失敗測試。新版原生驗證另有色彩附件、HLG 數值、Metal 顯示方向、資源預算、呈現世代與取消等測試，等待候選版 CI 最終結果。

新增的 GitHub `Native compile and tests` 僅供手動執行，不需要簽章金鑰，不上傳 TestFlight。日常新版封裝仍使用既有 Codemagic 工作流程。

## 實測界線

這次有程式、回歸測試與原生編譯驗證，不以模擬器或單元測試冒充手機效能測量。iCloud 尚未下載的素材、相簿取檔、長 GOP 的首次隨機定位，以及多層實際可見的 4K 影片仍有讀取和解碼成本。工作檔仍以整支素材準備，沒有加入分段代理儲存系統。

上機應使用同一台裝置和同一批本機素材，比較冷進場、首次來回拖曳、停手精準畫面、快速播放／暫停，以及調整圖片透明度、字體、馬賽克時的畫面。診斷中的原生快取命中、實際呈現次數及延遲可確認是否走到新路徑。HDR 顯示與實際裝置的亮度、色調映射仍須真機確認；截圖不能代替 HDR 呈現的判斷。
