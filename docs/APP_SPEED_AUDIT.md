# App 速度與畫質檢查（2026-09-05）

目標：顏色準、HDR 保留、滑動預覽快速、樣式更新即時，以及批次匯入／匯出順暢。

## 本輪修改

後續圖片眼睛開關：圖片專用軌保留在預覽合成，以 `setHiddenImageTracks` 即時更新可見性；影片、混合軌仍走結構重建。原生只在預覽讀取此狀態，匯出保持原本的隱藏軌過濾。新合成建立時帶入可見性，完成後再同步最新值；不支援新通道則退回重建。切換不重建的 widget 回歸與 HDR／時間軸尾端測試共 23 項通過，iOS 原生編譯及實機閃動尚待驗證。本次未調整色彩增益。

| 範圍 | 改動 | 保留條件 |
| --- | --- | --- |
| 批次大預覽 | 照片以長邊 1440 的預覽解碼，避免每次切換都讀完整原圖到 Dart | 匯出仍讀原始完整尺寸；HDR 匯出保留原生路徑 |
| 批次照片匯出 | 直接用檔案路徑建立解碼器，減少原檔在 Dart 記憶體的複製 | 新舊路徑的完整輸出像素比對一致；Web 繼續使用 bytes |
| 重複浮水印 | 同尺寸、同設定的影片與 HDR 照片，於同一批次重用浮水印 PNG | 設定或尺寸改變即重做；只留一份，最多 16 MiB；不跨批次 |
| 批次影片 | 讀取已有的影片中繼資料及長度，不再為每支影片額外建立播放器 | 資料不足仍使用播放器保底；位元率、HDR、輸出尺寸規則不變 |
| 拖曳預覽 | 單格解碼失敗不再中斷佇列，繼續處理最新目標 | 舊代結果作廢、播放／離頁清理等規則仍保留 |

## 量測與驗證

- Windows 暖機後，6 次相同 1080×1920 浮水印：原本 755 ms，重用後 140 ms；PNG 位元組相同，實際繪製從 6 次變成 1 次。這是浮水印製作階段約減少 81% 的耗時，**不是整批匯出或 iPhone 的加速比例**。
- 跨批次、匯入順序、HDR 參數、預覽／匯出位置、滑動佇列及樣式同步的定向測試：94 項通過，1 項大型效能量測預設略過。其後另行執行上面的浮水印量測。
- 全 App 靜態檢查通過；全 App 非截圖測試 442 項全部通過（含 20 萬次隨機操作壓力測試），結果見 `build/app_speed_audit_tests.log`。
- iOS 原生白色／中灰與透明度像素測試已存在，但 Windows 無法執行 Swift／Core Image；不以 Dart 測試替代 iPhone 色彩驗證。

## 已檢查、仍受限制的部分

- 相簿匯入使用原始表示法，避免系統先重壓影片；仍需要把選中的檔案存到 App 可持續使用的位置。iCloud 未下載素材的網路時間不能由編輯器省略。
- 照片匯出已有兩段流水線。大型照片的解碼、合成與寫入繼續保持有界，不增加無上限的全尺寸並行。
- 影片硬體編碼及相簿寫入仍可能是總耗時的大宗；本輪沒有降低解析度、畫質或關閉 HDR。
- 樣式更新保留最新版本同步與手勢中的快速預覽；停止操作後補高解析。原生色彩與暫停重畫是否正常仍須實機測試。

## iPhone 驗收

使用同一批本機素材比較新舊版本：20 張 HEIC、10 支 SDR／HDR 影片及混合批次，記錄選取完成至可操作、全部縮圖完成、全部匯出存入相簿的時間。另以 100% 不透明白底／彩色圖片覆蓋 HDR 影片，檢查預覽與匯出；連續來回滑動與調樣式後，確認最後一個值與輸出一致。桌面測試不代表已通過這些項目。
