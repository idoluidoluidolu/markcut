# 編輯器操作與效能修正（2026-09-29）

本輪承接既有資安及大型編輯器調整，處理使用者回報的操作問題。修改尚未發佈到手機或商店。

## 修改內容

- **素材放大**：圖片／影片的滑桿、雙指縮放及滑鼠滾輪統一支援最高 100 倍。高倍率 FFmpeg 匯出改用反向座標取樣，工作影格不再隨放大倍率平方增加。
- **草稿時間軸縮圖**：新增最多 128 MiB 的可重建磁碟快取，驗證來源路徑、大小、修改時間及片長；草稿重新開啟時直接還原。尚無快取時，先顯示已取得的縮圖，再逐步補齊，避免等整條解碼完成才出現。
- **裁切套用**：裁切範圍經即時變形通道送到現有 iOS 預覽；圖片改為保存裁切參數，不在按套用後重新編碼整張原圖。原檔保留，可重新調整及復原。
- **裁切後移動**：移動、磁吸、置中、縮放錨點與選取框使用裁切後可見區域。允許原圖中心在畫布外，修正小範圍裁切無法移到中央；大小滑桿也保留可見中心。FFmpeg 同步修正裁切後鏡像／旋轉的定位。
- **素材文字**：輸入區可顯示 3–6 行並捲動，提供靠左／置中／靠右。排列保存於草稿、複製與復原資料，共用文字繪製器同步用於預覽及匯出。
- **文字完成按鈕**：浮水印輸入框聚焦時在上方顯示「完成」，收起鍵盤並保留輸入；素材文字視窗也有完成按鈕。多行換行鍵維持換行功能。浮水印框從一行隨內容增高，避免固定六行使批次照片頁被鍵盤遮住。
- **速度微調**：0.25–4 倍之間每格 0.01 倍，可用加減按鈕精調，另提供 1.1、1.2、1.25 等常用值。倒轉仍在滑桿放手後才切換方向；片段長度及匯出使用相同的速度數值。
- **修剪時縮圖固定**：時間軸縮圖磚錨定原始素材時間，左／右把手只揭露或遮住既有縮圖，不再重新分配整條影像。包含正播、倒播與非整數倍速，保留可見範圍內才建立縮圖元件的效能設計。
- **意見回饋**：未送出時點擊對話框外可關閉，送出中的既有保護保留。
- **容量與清理**：個人頁新增「容量與清理」，分列草稿、GIF、範本、貼圖、預覽縮圖及未使用的轉檔暫存。分類可進入原有管理清單。清理保留已儲存作品，並與草稿儲存及縮圖寫入序列化；草稿引用不明或編輯器仍開啟時不清除工作檔。

## 驗證範圍與限制

最終定向回歸使用單一測試程序 `--concurrency=1`：**110 passed、0 failed、0 skipped**，1 分 40 秒，exit 0。涵蓋草稿縮圖還原、漸進顯示、清理與引用保護、實際 FFmpeg 高倍率像素輸出、裁切即時通道、可見中心拖曳與滑桿縮放、文字多行與排列、鍵盤完成按鈕、速度微調、修剪縮圖定位及頁面 golden。指令及原始紀錄保留於忽略版控的 `build/verify-editor-recovery.bat`、`build/editor-fixes-recovery-tests.log`。

大型時間軸測試中，一小時片段僅建立 24 個縮圖元件，捲到尾端為 28 個；2,000 個片段的頁面初始掛載 24 個片段元件，捲動及固定選取後為 49 個。這些是虛擬化的回歸數字，不是手機 FPS。

`flutter analyze --no-pub --no-fatal-infos lib test` 完成：**0 error、0 warning**，保留 1 個既有函式宣告風格 info，exit 0。分析工具在原中文路徑的通訊初始化失敗後，改從既有 ASCII junction 執行成功。紀錄為 `build/editor-fixes-recovery-analyze.log`。`git diff --check` 通過。

本輪完整測試套件與 Android 建置曾因執行環境中斷而未完成，未列為通過。恢復時發現編輯器、浮水印面板及一個測試檔內容變成全零；從編譯快取取回程式碼並恢復測試後，完成上述 110 項回歸。另保存修改檔備份 `build/recovered-editor-sources-20260929.zip`。未據此判定當機原因。

Windows 無法執行 Xcode 或 iPhone 真機。iOS 的 Swift／Metal／Core Image 修改目前能審查原始碼並驗證 Dart 通道契約，仍須 macOS 編譯與真機確認 HDR、裁切套用時機、鍵盤及高倍率預覽；桌面測試不代表手機實際延遲或 FPS。

先前資安、供應鏈與後端驗證的未結項目仍見 [APP_REMEDIATION_2026_09_27.md](APP_REMEDIATION_2026_09_27.md)，本輪不把那些項目視為已排除。

## 2026-10-01 續修：鍵盤、更新後草稿、HDR 縮圖

- 素材文字面板按鍵盤上方的可用高度縮小，輸入時保留完整預覽；多行內容可在輸入框內捲動，「完成」固定在控制項捲動區外。測試涵蓋 390×844、375×667、瀏海與底部安全區、八行文字及捲動後關閉。
- 草稿載入會將舊 iOS Data/Application 沙盒路徑對應到目前目錄。涵蓋影片／圖片／聲音素材、HDR 與 SDR 工作檔、倒轉來源、照片／批次／拼圖／GIF 草稿，以及批次個別設定的路徑鍵。僅處理已知媒體欄位與目錄，不猜測同名檔，也不改動文字內容。
- 清理與容量統計所用的引用清單、工作檔索引、草稿複本與選取器複本保留清單同步處理舊路徑。缺少原檔時，可從仍存在的索引工作檔救回；HDR 模式優先保留 HDR 代理，原備份不會在複製完成前被搬走。
- 影片與拼圖若仍有檔案或資料讀不到，停在說明頁，原草稿不被殘缺版本覆寫；批次草稿也不再默默略過缺檔後開啟可存回的殘缺版本。載入中途離開同樣不保存半成品。
- 草稿封面與時間軸縮圖按目前 HDR 模式選取原檔／代理，避免 HDR 預覽卻讀舊 SDR 工作檔。iOS 抽 JPEG 改由 AVFoundation 先做 SDR 映射，再明確轉成 sRGB；不再依賴只辨認 HLG／PQ 的條件判斷。依據 [Apple dynamicRangePolicy 文件](https://developer.apple.com/documentation/avfoundation/avassetimagegenerator/dynamicrangepolicy-swift.property)，使用 `forceSDR`；舊系統沿用預設 SDR 行為。
- 縮圖磁碟快取升為 v3 並納入實際取圖路徑，HDR 與 SDR 版本不混用。舊時間軸快取會按需重建；草稿封面在開啟編輯並保存時更新，不在啟動時同時解碼所有草稿。

本輪定向回歸共 **151 個不同測試通過**，分批單程序執行；涵蓋真實暫存檔的目錄搬移、四種草稿卡續作、缺檔保護、從搬移後的 HDR 索引救援、清理、縮圖來源與快取、既有裁切／速度／手勢及草稿持久化。原始紀錄：`build/draft-keyboard-tests2.log`（34）、`build/draft-regression-tests.log`（115）、`build/draft-final-tests.log`（重跑 9 個及新增 2 個）。靜態檢查仍僅有既有的 `prefer_function_declarations_over_variables` 提示，無錯誤或警告。

Windows 未編譯 iOS 原生程式，也未驗證手機上的最終 HDR 顯示。JPEG 草稿縮圖是 SDR，不能承諾與 HDR／EDR 播放器的高光亮度完全一致；建置後應用同一份 iPhone HLG／Dolby Vision 素材比對色調、灰階與高光。路徑修復僅能找回 App 容器內仍存在的素材或備份；若 App 複本已被系統清除，只有相簿原檔仍存在，且沒有可用工作檔，就無法靠改路徑自動還原。舊版已覆寫掉的時間軸資料也不能由此修復重建。
