# 大型編輯器效能調整（2026-09-27）

此輪接續 APP 安全修正，處理大型時間軸、重建範圍、音訊波形、iOS 紋理載入及自動存檔。修改保留在目前工作目錄，尚未提交或發版。

## 已實作

### 1. 編輯器區域更新與內容版本分離

- 預覽、控制列、時間軸、浮水印及匯出分區具有獨立更新訊號，AppBar／分頁導覽保留穩定 widget identity。
- 單純選取／取消選取不再重建整個 `VideoEditorScreen`、AppBar、TabBar，也不增加供原生預覽指紋使用的內容版本。
- HDR 判定改由素材更新觸發，不再依賴匯出分頁的 build 副作用；舊來源的非同步探測結果也不能覆蓋新來源。測試不經過匯出頁就驗證 HDR 預覽與浮水印。
- 繼承的螢幕尺寸、文字比例或主題變更仍會更新各區域；縮窄同一個編輯器視窗時工具列重新排版，內容版本不變。
- 匯入、切割、刪除等內容變更繼續完整失效處理。畫布拖曳與修剪原有的每幀局部更新路徑保留。
- 合成換手的 1.7 秒保底計時器可取消，重建合成與離頁時不再留下舊計時器。

### 2. 雙向時間軸虛擬化

- `TimelineViewportIndex` 每個內容版本建立一次軌道索引，包含各軌排序、最大結束時間前綴、ID 查詢、軌數及時長。
- 水平僅建立附近片段，垂直以留白保留完整捲動高度，只建立可見及緩衝軌道。滑動在跨越分區時才更新元件。
- 選取、拖曳中的片段與軌道會保留，避免捲動途中卸載手勢狀態；處理跨越可視起點的長片段與舊資料重疊片段。
- **2,000 片段／20 軌測試**：初始掛載 24 個片段元件，捲到另一端並保留遠端選取後為 49 個。

### 3. 長片段內部也按可視範圍繪製

- 縮圖只建立附近 tile，保留全片段座標以正確對應 trim／reverse 與縮圖取樣。
- 移除「只顯示前 400 張 tile」的截斷；一小時片段尾端仍有縮圖。
- 實測一小時片段的縮圖 widget：起點 24 張、尾端 28 張。
- 音訊與錄音波形也只掃描可見柱狀範圍，避免高倍率下遍歷整段寬度。

### 4. 波形訂閱與有界資源

- 每個檔案有自己的更新訊號，解碼完成僅通知使用該檔案的元件。
- 可見片段持有 cache lease；使用中的結果不因原本 12 筆 LRU 上限而互相淘汰。
- 單一 decoder、取消、timeout 與 PCM 預算保留；最多容納 128 個已完成／排隊項目，超額需求等待容量，離開後取消。
- 每份波形最多 6,000 個 Float32 樣本，128 份樣本 payload 約 2.93 MiB（不含物件、decoder 與 PCM 暫存）。離開後最多保留 12 份冷快取。
- 32 個使用中檔案回歸測試確認各解碼一次、各自通知一次；容量壓力測試確認不淘汰使用中的資料。

### 5. iOS 靜態圖片／GIF 背景載入

- 相鄰時間窗口採差異更新，仍需要且符合預算的紋理繼續使用。
- ImageIO 縮圖解碼與 Metal texture upload 移到單一背景佇列；主執行緒只接收最新有效結果。
- 僅允許一個尚未完成安裝的解碼工作；快速拖曳會取消舊窗口，GIF 在幀及時間資料迴圈檢查取消。
- 已安裝紋理與目前工作的預算一併計算；沿用 128 MiB、記憶體警告後 64 MiB 的 cache 目標及單 GIF 上限。此數字不是整個 App／GPU 峰值保證，ImageIO、上傳中資源及系統配置仍有額外記憶體。
- 完成後增加繪製版本，靜止預覽也能補畫。離開編輯器／記憶體警告取消待處理工作，舊結果不得重新安裝。
- **Windows 無法編譯／執行 iOS。以上原生變更完成程式碼檢查，仍需 macOS 編譯與 iPhone 實測。**

### 6. 專案保存先於封面

- 自動存檔先保存專案內容、引用與現有縮圖，再以單一工作合併更新封面。
- 封面以保存版本驗證，僅更新封面與索引，不重新寫入整份專案，也不能覆蓋新保存或復活已刪除草稿。
- `DraftStore` 在非同步 JSON 編碼之前保留佇列次序，避免慢的舊保存超越新保存／刪除。
- 測試涵蓋最新內容、引用、保存時間不被封面改寫，以及晚到封面、新保存、刪除的競態。
- 縮圖進場測試使用與 Timer 相同的可控時鐘，另驗證原生抽幀不回覆時五秒放行；裁切測試等待路由就緒，取代固定等待八幀。

## 量測與驗證

環境為 Windows、Flutter 3.44.8／Dart 3.12.2；widget benchmark 使用 debug 與部分原生 mock，**不代表手機 release FPS**。

| 項目 | 本輪結果 |
|---|---|
| 大型時間軸 | 2,000 片段初始掛載 24 個；捲動＋遠端選取 49 個 |
| 一小時片段 | 起點／尾端縮圖 widget 24／28 個 |
| 選取回歸 | 根畫面、AppBar、TabBar 重建皆為 0，內容版本不變 |
| 定向測試 | 第一組 39 passed；長片段、時間軸捏合、修剪、縮圖取樣 29 passed |
| 最終程式碼獨立驗證 | benchmark、視窗尺寸變更、選取／拖曳、HDR／SDR 浮水印共 14 passed；前一組競態回歸 44 passed |
| 整頁 benchmark | 每次整頁更新重建 671 → 564 elements（約減少 16%） |
| Flutter 完整套件（含 golden、桌面 FFmpeg） | **1,089 passed、7 skipped、0 failed**；20 分 55 秒，exit 0，concurrency=2 |
| Dart 靜態分析 | 0 error、0 warning；1 個既有函式宣告風格 info |
| Android debug APK | **BUILD SUCCESSFUL**；9 分 57 秒，422 tasks（24 executed／398 up-to-date），exit 0 |

保留未改善的量測：同工作站既有整頁更新 median／p90 為 30.06／55.60 ms，最終程式碼為 **30.19／83.15 ms**（中途一次為 38.38／117.58 ms）；選取為 28.44／47.75 ms。build phase median 由 5.13 降到 3.95 ms，但 layout 仍有尖峰。**小型專案整頁更新的中位數沒有明顯改善，p90 反而較高，不能宣稱已達 60 FPS。** 確定改善的是大型專案的元件／繪製工作量、選取時的更新範圍與資源界線。

最終單指拖曳 median／p90 為 2.58／7.17 ms，雙指縮放為 4.72／15.78 ms。以上皆為桌面 debug，沒有手機 GPU／解碼器的實機幀時間證據。

本機紀錄放在忽略版控的 `build/editor_perf_2026_09_27/`：`before.log`、`after-bench.log`、`editor-final.log`、`focused3.log`、`focused4.log`、`regressions-final.log`、`full-tests-final.log`。初輪完整執行的失敗紀錄也保留在 `full-tests.log`：HDR 初始化與時間相依測試修正後，重新執行完整套件通過。

最終靜態分析為 `analyze-final3.log`，Android 建置為 `android-final.log`。Android 沿用第一輪的 ASCII junction 與停用 Kotlin incremental 的本機環境處理，另將 Gradle workers 限為 2；沒有更改產品設定來規避檢查。Gradle 仍顯示既有 Flutter／外掛的 Kotlin、AGP 棄用警告，並非全工具鏈零警告。未更新任何 golden 基準來通過本輪效能調整的驗證。

本輪新產物為 `build/app/outputs/apk/debug/app-debug.apk`，376,156,304 bytes；這是 debug 驗證產物，未產生或發佈本輪的正式 release 包。
